# Discovery Plan: EVDI 云桌面产品定位与差异化

**日期**: 2026-06-20
**产品阶段**: 现有产品架构升级（已有付费客户）
**发现问题**: 在已有付费客户和国内 VDI 竞争格局下，EVDI 的零客户端+高级功能双轨策略能否形成可持续的差异化定位？

---

## 背景

### 产品现状

- EVDI 是已有付费客户的商业云桌面产品
- 正在从现有架构升级到 K8s+KubeVirt+WebRTC 云原生架构
- 架构升级的核心驱动力：① 实现零客户端（浏览器访问）能力 ② 提升扩展性、降低运维成本
- 技术架构升级不带来客户感知，是内部工程决策

### 竞争格局

| 竞品类型 | 代表厂商 | 特点 |
|----------|----------|------|
| 国内专业 VDI | 深信服、锐捷、青云 | 私有协议+重型客户端，安全合规积累深 |
| 国内大厂云桌面 | 华为 FusionAccess、阿里云桌面 | 品牌+渠道+生态优势，价格有规模效应 |
| 国际传统 VDI | Citrix、VMware Horizon | 功能最全，定价高，在中国市场萎缩 |

### 已确认的事实

- ✅ 零客户端（浏览器访问）是核心客户需求
- ✅ 部分高级功能（USB/多屏/文件拖放）需要 Tauri 原生客户端
- ✅ 产品基于开源组件构建，但产品本身闭源商业化
- ✅ MVP 已验证 WebRTC 视频 + WebSocket 键鼠输入基本链路

### 根本问题

**问题 A：零客户端是不是杀手级差异化？**

| | 零客户端是决策因素 | 零客户端只是加分项 |
|--|------------------|------------------|
| 如果是 | 产品定位聚焦"零客户端 VDI"，全力投入 WebRTC 体验优化 | — |
| 如果不是 | — | 需要找其他差异化点（安全/价格/垂直场景），零客户端降级为卖点之一 |

**问题 B：WebRTC 体验能否匹敌竞品私有协议？**

| | WebRTC 体验可匹敌 | WebRTC 体验有差距 |
|--|------------------|------------------|
| 如果是 | 零客户端差异化成立，架构升级值得投入 | — |
| 如果不是 | — | 需要备选方案（WebRTC+私有协议双栈），架构升级方向需调整 |

**依赖链：B → A。WebRTC 体验不过关，零客户端再重要也站不住。**

## 验证实验

### G1: WebRTC 体验可行性（验证 H4）

| 项目 | 内容 |
|------|------|
| **假设** | WebRTC 在弱网/跨运营商场景下的体验不低于深信服/锐捷私有协议 |
| **方法** | 对比测试：搭建 EVDI Agent + 竞品 VDI 并行环境，5-8 个现有客户 A/B 盲测 |
| **测试场景** | ① 局域网（基准）② 跨运营商（电信↔联通）③ 弱网模拟（2%丢包、100ms抖动）④ 跨国（如有需求） |
| **测量指标** | 输入延迟（键鼠→画面响应）、画质 MOS 评分、断线重连时间 |
| **成功标准** | 弱网场景下 WebRTC 延迟 ≤ 竞品 +20%，MOS 评分差异 ≤ 0.5 |
| **工作量** | 2 人周 |
| **时间线** | 第 1-2 周 |

**实验细节：**

- **Hypothesis**: 如果 WebRTC 弱网体验与竞品差距在 20% 以内，零客户端的便利性优势可以抵消体验差距
- **Setup**: 准备两个测试环境（EVDI + 竞品），使用 same desktop workload（文档编辑+浏览器+视频播放）
- **Measurement**: 使用高速摄像头录制键鼠输入到画面响应的时间差（客观），MOS 评分（主观）
- **Decision**: 如果弱网延迟差距 >30% → 需要考虑 WebRTC 优化或混合协议方案

### G2: 零客户端购买驱动力（验证 H1、H2）

| 项目 | 内容 |
|------|------|
| **假设** | 零客户端是客户选择 EVDI 的首要决策因素，且能吸引竞品客户切换 |
| **方法** | 客户深度访谈：8-10 个现有客户 + 3-5 个竞品潜在客户 |
| **访谈重点** | ① VDI 部署痛点排序 ② 零客户端在决策中的权重 ③ 切换方案最大阻力 ④ 什么条件下愿意切换 |
| **成功标准** | ≥60% 受访者将"零客户端/免安装"列为 Top 3 购买因素；≥30% 竞品客户表示愿意评估 |
| **工作量** | 1 人周准备 + 2 周执行 |
| **时间线** | 第 1-3 周 |

**访谈脚本要点：**

1. 您当前 VDI 部署中，最痛的 3 个问题是什么？
2. 如果浏览器可以直接访问远程桌面，不需要安装任何客户端，这对您的决策有多大影响？（1-10 分）
3. 从现有方案切换到新方案，您最担心什么？（数据迁移/稳定性/运维培训/其他）
4. 什么条件下您会考虑切换 VDI 方案？

## 决策框架

### 场景 1: WebRTC 体验可匹敌 + 零客户端是决策因素 ✅✅

→ **产品定位：零客户端 VDI 领导者**
- 核心信息：浏览器 5 秒进入桌面，Tauri 解锁专业能力
- 投入重点：WebRTC 体验极致优化、零客户端营销
- 高级功能策略：Tauri 作为增值，Web 端覆盖 80% 场景

### 场景 2: WebRTC 体验可匹敌 + 零客户端是加分项 ✅⚠️

→ **产品定位：需要找其他核心差异化点**
- 分析 TCO/安全合规/垂直场景哪个是更强决策因素
- 零客户端降级为"卖点之一"，不是定位核心
- 重新评估资源投入比例

### 场景 3: WebRTC 体验有差距 + 零客户端是决策因素 ⚠️✅

→ **技术路线调整：混合协议方案**
- 考虑 WebRTC+私有优化双栈：弱网场景自动切换私有协议
- 零客户端作为定位不变，但需要补齐弱网体验短板
- 延长架构升级时间线

### 场景 4: WebRTC 体验有差距 + 零客户端是加分项 ⚠️⚠️

→ **重大方向调整**
- WebRTC 降级为"轻量访问方式"，不是核心架构
- 重新评估架构升级是否值得投入
- 考虑在现有架构上增加浏览器访问能力（渐进式方案）

## 附录：已排除的假设

以下假设在发现过程中因认知校准而被排除：

| 原假设 | 排除原因 |
|--------|----------|
| 开源社区会采纳 EVDI 基础版 | 产品闭源商业化，不存在开源社区获客 |
| 开源版不会蚕食付费版 | 产品无免费版，不存在蚕食问题 |
| 客户能感知技术架构升级价值 | 明确确认架构升级不带来客户感知 |
| 开源+付费模式在中国市场可行 | 商业模式不是开源+付费，而是闭源商业授权 |
| 目标客户已有 K8s 运维能力 | 架构升级是内部决策，客户无需感知 K8s |
