## 决策框架

### G1: 双轨策略

| 结果 | 行动 |
|------|------|
| ✅ 通过（Web 覆盖 ≥75%，安装意愿达标，代码复用 ≥60%） | 确认双轨策略，Web 为 MVP 核心，Tauri 为 Pro 版 |
| ❌ 失败（Web 覆盖 <60% 或代码复用 <40%） | 重新评估：全力 Tauri 单轨或缩小 Web 功能范围 |
| ⚠️ 部分通过 | Web 限定轻量场景（办公/浏览），Tauri 覆盖全部专业场景 |

### G2: Rust 渲染管线

| 结果 | 行动 |
|------|------|
| ✅ 通过（wgpu 延迟 <25ms，3 平台兼容，学习曲线可接受） | Tauri 采用 wgpu 渲染，启动渲染管线开发 |
| ❌ 失败（wgpu 延迟无优势或兼容性差） | Tauri 回退 Canvas 渲染，Rust 仅用于系统级 Hook |
| ⚠️ 部分通过 | wgpu 仅用于特定场景（多显示器/4K），其余用 Canvas |

### G3: DataChannel

| 结果 | 行动 |
|------|------|
| ✅ 通过（双向修复成功，多路复用性能达标） | 输入事件回归 DataChannel，移除 WebSocket 临时方案 |
| ❌ 失败（双向无法修复） | 保持 WebSocket 输入方案，DataChannel 仅用于剪贴板/文件 |
| ⚠️ 部分通过 | 键鼠走 DataChannel，大块数据走 WebSocket 双通道 |

### A4: 浏览器兼容性

| 结果 | 行动 |
|------|------|
| ✅ Chrome/Firefox ≥95%，Safari ≥80% | 正式支持三大浏览器 |
| ❌ Safari 严重受限 | Safari 降级为有限功能，文档标注已知限制 |

### A19: USB 实时性

| 结果 | 行动 |
|------|------|
| ✅ HID 类设备可行 | USB 重定向纳入 Tauri P1 功能 |
| ❌ HID 类设备也不可行 | USB 重定向降级为 P2，优先做文件拖放替代方案 |

## 淘汰/延后清单

| 创意 | 决定 | 原因 |
|------|------|------|
| E-5: 离线 PWA 模式 | **淘汰** | 影响度低，投资回报不确定，改善重连体验(D-3)更有价值 |
| D-5: 多桌面切换器 | **延后到 V2** | 需先验证多桌面使用率（A34=40%），V1 不投入 |
| PM-5: AI 桌面助手 | **延后到 V2+** | 核心体验未验证前不做 AI 增值功能 |
| PM-2: 统一工作空间门户 | **延后到 V1.5** | 先做纯远程桌面体验，门户功能迭代叠加 |
| PM-4: 零信任安全内置 | **V1 基础版** | V1 仅做水印+剪贴板策略，完整零信任延后 |
