# PRD: EVDI 云桌面客户端 V1 MVP

## 1. Summary

本文档定义 EVDI 云桌面平台客户端层（L1）V1 MVP 的产品需求。V1 采用 **Web + Tauri 双轨渐进式策略**：Web 客户端通过浏览器零安装访问远程桌面，覆盖日常办公场景；Tauri 原生客户端解锁 USB 重定向、多显示器、文件拖放等专业能力。两者共享同一套 Broker API 和 WebRTC 传输层，最大化代码复用。

## 3. Background

### 3.1 为什么做这个产品

企业云桌面市场正在从传统本地部署转向云原生 DaaS 模式（Gartner 预测 2026 年 60% VDI 将云原生化）。现有方案（Citrix、VMware Horizon）依赖私有协议和厚重客户端，企业面临：

- **部署复杂**：需要安装专用客户端，IT 管理员推送更新成本高
- **许可证昂贵**：按用户计费，中小企业难以承受
- **技术封闭**：私有协议（ICA、PCoIP）无法深度定制

EVDI 基于 **WebRTC 开放标准** 构建，天然具备浏览器零安装访问能力，同时通过 Tauri 原生客户端提供专业级功能，形成差异化的双轨策略。

### 3.2 为什么是现在

- MVP 已验证核心链路：WebRTC 视频 + WebSocket 键鼠输入，桌面画面与交互正常工作
- Pion WebRTC v4 趋于稳定，DataChannel 问题是最后的技术阻碍
- 市场窗口：Broadcom 收购 VMware 后客户正在重新评估 VDI 方案
- WebRTC 浏览器支持成熟，Chrome/Firefox/Edge 原生支持

### 3.3 有什么新变化

- MVP 验证了 Pion WebRTC + GStreamer 编码链路的可行性
- 发现 DataChannel Lite ICE 单向性问题，已有 WebSocket 回退方案
- Tauri v2 发布，原生能力（系统 Hook、USB）比 v1 更成熟

## 4. Objective

### 4.1 核心目标

**让用户通过浏览器 5 秒内进入远程桌面，重度用户通过安装 <15MB 原生客户端获得完整专业体验。**

### 4.2 关键结果（OKR）

| # | 关键结果 | 目标值 | 衡量方式 |
|---|----------|--------|----------|
| KR1 | Web 客户端连接成功率 | ≥95% | 成功建立 WebRTC 连接 / 尝试连接 |
| KR2 | Web 客户端端到端操作延迟 | <150ms（局域网） | 键鼠输入到屏幕响应的时间差 |
| KR3 | Web→Tauri 升级转化率 | ≥20% | 安装 Tauri 的 Web 用户占比 |
| KR4 | 首次使用到进入桌面时间 | <60 秒 | 从打开页面到看到桌面画面的时间 |
| KR5 | 断线重连成功率 | ≥90% 在 5 秒内 | 网络波动后自动恢复连接的比例 |
| KR6 | 两端代码复用率 | ≥65% | 共享代码行数 / 总代码行数 |

### 4.3 战略对齐

- **L1 客户端层**是七层架构的用户触点，直接决定用户对 EVDI 的第一印象
- 双轨策略与 Broker 的 `clientType` 字段设计对齐，同一用户可切换客户端类型
- WebRTC + DataChannel 是 Agent（L2）的唯一直接交互通道，客户端能力决定 Agent 通道设计

## 7. Solution

### 7.1 UX / 用户流程

#### 7.1.1 Web 客户端主流程

```
用户打开浏览器
    │
    ▼
登录页（JWT 认证）
    │
    ▼
桌面列表页
    │  显示可用桌面、运行状态、最近连接
    │  首次使用：3步引导（选择桌面 → 连接 → 进入）
    │
    ▼ 选择桌面 → 点击"连接"
    │
    ▼
连接中（占位画面 + 进度提示）
    │  步骤：获取TURN凭证 → WebSocket信令 → SDP协商 → ICE连接 → 媒体流
    │  超时/失败：显示错误 + 重试按钮
    │
    ▼
远程桌面（全屏模式）
    │  Canvas渲染视频流 + 键鼠输入
    │  边缘触发浮动工具栏
    │  网络波动 → 占位画面 → 自动重连
    │
    ▼ 关闭/断开
    │
    ▼
桌面列表页（返回）
```

#### 7.1.2 Tauri 客户端额外流程

```
Tauri 启动
    │
    ▼
系统托盘常驻
    │  快速连接最近桌面
    │  桌面状态通知
    │
    ▼ 连接桌面
    │
    ▼
原生窗口（全屏/窗口/多显示器）
    │  Rust Hook: 拦截系统快捷键（Ctrl+Alt+Del等）
    │  wgpu渲染 / Canvas回退
    │  USB设备检测 → DataChannel隧道
    │  文件拖放 → DataChannel传输
    │  会话水印（透明叠加层）
    │
    ▼
断开 → 后台保持 → 系统托盘
```

```

              │
              ▼
```

#### 7.3.3 DataChannel 多路复用协议

```
单条 DataChannel 上的虚拟通道帧格式：

┌──────┬──────┬────────────┬─────────────────────┐
│ Chan │ Type │  Length    │      Payload         │
│ 1B   │ 1B   │  2B        │  variable            │
└──────┴──────┴────────────┴─────────────────────┘

通道编号：
  0x01 = 键盘输入 (reliable, ordered)
  0x02 = 鼠标输入 (reliable, ordered)
  0x03 = 剪贴板   (reliable, ordered)
  0x04 = 文件传输 (reliable, ordered)
  0x05 = USB HID  (reliable, ordered)
  0x06 = 心跳     (unreliable)
  0x07 = 码率反馈 (unreliable)
```

### 8.7 关键依赖与风险

| 依赖 | 风险 | 缓解措施 |
|------|------|----------|
| Pion DataChannel 双向通信 | 键鼠输入必须走 WebSocket 回退，增加延迟 | 实验 7 验证，如失败则 WebSocket 长期方案 |
| wgpu 渲染性能 | Tauri 无渲染加速优势 | 实验 4 验证，Canvas 作为始终可用的回退 |
| Tauri v2 稳定性 | 生产环境可能遇到未知问题 | 密切跟踪 Tauri 社区 issue |
| 浏览器 Clipboard API | 需要用户授权，可能被安全策略阻断 | 提供手动粘贴替代方案 |
| Rust 人才 | 团队 Rust 经验有限 | 渐进式引入，Tauri 原生层逐步替换 |
